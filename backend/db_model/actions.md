# Quests

## Get quests
- Simple list of quests - name, id, description, points, estimated duration, num of steps
- only return those whose `available_from` < now < `available_to` (only those that are active)
- route - GET /quests
- order by created_at
- Ability to filter
    - status - active, expired (active by default)

## Get quest detail
- GET /quest/{id}
- All data - also steps with id, name, type, order
    - quests ordered by order
- created_at as well
- do not return created_by!!!

## Start Quest:
- POST/PUT /quest/{id}/start
- Called by user, ust be autenticated
- When called, create new entry in quest_enrollments
    - user_id, quest_id references
- validate quest is active, and date from, to available match
- Data path - create path using this form:
    - s3://${monad-bucket}/experiments/2025/10/7/:user_id/:quest_id/
    - we will store data generated by this experiment here
- completed_at null
- Create quest_step_completion records for al 

Return data:
- Create records for all quest_step completion entries of user, then send him list of steps, ids, action, type, desc, ... 
- Create records for each step - status in progress by default, created_at now, started_at, step specific data, ....
```
{
  enrollment_id: uuid,
  quest: {
    id: uuid,
    name: string,
    description: string,
    steps: [
      {
        step_id: uuid,
        step_completion_id: uuid,  // ← Pre-created completion record
        name: string,
        type: quest_step_type,
        order: number,
        config: jsonb
      }
    ]
  },
  data_path: string,
  started_at: timestamp
}
```

## Complete Quest
- POST /quest/{quest_id}/complete
- The quest execution is done on the device. All data is stored on the device locally
- The data will be sent in bulk after the quest is completed
- This endpoint receives all the data in a JSON structure

### Request Body Structure
```json
{
  "enrollment_id": "uuid",
  "completed_at": "timestamp",
  "steps": [
    {
      "step_completion_id": "uuid",
      "status": "completed | failed | skipped",
      "started_at": "timestamp",
      "completed_at": "timestamp",
      "step_data": {
        // Step-specific data (optional)
        // For scan_qr: { "qr_value": "...", "scanned_at": "..." }
        // For walk_to: { "coordinates": {...}, "arrived_at": "..." }
        // For connect_to_ap: { "ssid": "...", "connected_at": "..." }
      },
      "skip_record": {
        // Only for failed/skipped steps
        "message": "string",
        "error_code": "string",
        "metadata": {}
      }
    }
  ],
  "data_file": {
    // Optional - reference to uploaded compressed logs/data
    "filename": "string",
    "size": "number",
    "checksum": "string"
  }
}
```

### Backend Processing
1. Verify enrollment exists, belongs to authenticated user, and is in 'in_progress' status
2. Validate all step_completion_ids exist and belong to this enrollment
3. Update each quest_step_completion record:
   - Set status (completed/failed/skipped)
   - Update started_at and completed_at timestamps from client
   - Store step_data in step_data jsonb field
4. Create quest_step_skip_records for any failed/skipped steps
5. Update quest_enrollment:
   - Set status to 'completed' (or 'failed' if critical steps failed)
   - Set completed_at timestamp
6. Handle data file upload to S3 if provided (will be handled by internal API inside of app):
   - Upload to the data_path created during quest start
   - Update quest_enrollment.data_path with final file reference


### Validation Rules
- All step_completion_ids must reference pre-created records from quest start
- Cannot complete an enrollment that's already completed/abandoned
- Timestamps should be chronologically valid (started_at < completed_at)
- Quest must still be within available_from/available_to window (or allow grace period)

### Response
```json
{
  "success": true,
  "enrollment_id": "uuid",
  "points_earned": 100,
  "completed_at": "timestamp"
}
```

### Error Responses
- 400: Invalid step completion IDs or data structure
- 404: Enrollment not found
- 409: Enrollment already completed
- 403: Enrollment doesn't belong to authenticated user
